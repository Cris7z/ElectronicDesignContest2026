# 2026 H 题三板系统实施计划

> 计划版本：v1.0
>
> 日期：2026-07-31
>
> 唯一系统架构：**C07A 循迹/UI + STM32F103RCT6 滚球闭环 + 01Studio CanMV K230 视觉/图传**
>
> 当前状态：架构与控制器型号已确认；跨板 IO、供电和 D36A 台架安全尚未冻结。
>
> 当前唯一业务固件：`firmware/line_tracker/`

## 1. 唯一目标

本项目只实现 2026 年 H 题“车载平衡滚球运动控制系统”，不再保留其他主控组合或替代架构。

三块控制板的职责固定如下：

| 控制板 | 唯一职责 | 直接连接的主要对象 |
|---|---|---|
| C07A V1.1 / MSPM0G3507 | 红外循迹、左右轮驱动、启停按键、显示、底盘状态与整机任务入口 | CD4051 灰度、D103A/TB6612、轮编码器、OLED、BLS |
| STM32F103RCT6 | 钢球位置实时闭环、摆杆执行器控制、角度反馈、动态前馈、安全互锁 | D36A、42 型步进电机、MS42CG、C07A、K230 |
| 01Studio CanMV K230 | 摄像头采集、钢球位置测量、检测质量输出、实时图传、录像链路 | GC2093、STM32、场外接收/存储设备 |

以下边界不可改变：

- C07A 不处理摄像头图像，不产生 D36A 步进脉冲。
- STM32 不负责红外循迹、左右轮 PWM、图像处理或 RTSP。
- K230 不直接驱动电机、D36A 或安全使能。
- D36A、MS42CG、摆杆和钢球是 STM32 闭环的必要执行/反馈对象，不是第四套控制架构。
- 所有新增接线必须先进入正式接线表和 IO 表，再进入代码。

## 2. 赛题覆盖

| 需求 | 主要负责板 | 联合板 | 最终门槛 |
|---|---|---|---|
| H-R01 图传、录像、回放 | K230 | 场外接收设备 | 全摆杆清晰覆盖，实时显示，完整录像可回放 |
| H-R02 黑线一圈并停回 A | C07A | 无 | `≤20 s`，停车偏差 `≤2 cm`，显示总时间 |
| H-R03 静态 `+5 cm → -5 cm` | STM32 | K230 | `≤5 s`，最大绝对误差 `≤1 cm` |
| H-R04 A→B 动态居中 | STM32 | C07A、K230 | A→B `≤8 s`，球位置误差 `≤1 cm` |
| H-R05 整圈动态居中 | STM32 | C07A、K230 | 整圈 `≤30 s`，球位置误差 `≤1 cm` |
| H-R06 整圈任意指定点 | STM32 | C07A、K230 | 整圈 `≤30 s`，指定位置误差 `≤1 cm` |
| H-R07 其他 | 全系统 | 赛场规则 | 题面未细化，不自行增加要求；按现场正式说明留证 |
| H-R08 设计报告 | 全系统 | 测试记录 | 框图、流程、关键代码、理论和完整测试数据 |

H-R02 的“停回 A”与 H-R05/H-R06 的“通过 A”必须使用不同任务状态，不允许用同一停车逻辑混代。

## 3. 控制与数据链路

### 3.1 K230 → STM32

K230 只发送已经标定到摆杆坐标系的测量结果，最小字段为：

- 协议版本；
- 帧序号；
- 采集时间戳；
- 钢球位置 `x_mm`；
- 检测质量；
- 视觉状态；
- CRC。

STM32 必须用帧序号和时间戳判断重复、乱序和过期数据。检测丢失、质量不足或通信超时后，不得继续使用最后一次测量无限闭环。

### 3.2 C07A → STM32

C07A 向 STM32 提供：

- 当前任务模式；
- WAIT/RUN/FAULT 状态；
- 整机运行许可；
- 左右轮速度或等效底盘运动量；
- 弯道/转向量；
- 启动、停止和紧急停止事件；
- 状态序号与 CRC。

动态平衡阶段允许 STM32 使用底盘速度变化和转向量作前馈，但视觉位置闭环始终保留。

### 3.3 STM32 → C07A

STM32 返回：

- BOOT/READY/ARMED/RUN/FAULT 状态；
- 钢球位置和位置误差；
- 视觉是否有效；
- 摆杆角度/编码器是否有效；
- D36A 是否允许使能；
- 故障码；
- 心跳与 CRC。

C07A 只有在 STM32 READY、通信新鲜且无故障时才允许进入需要滚球控制的任务。

## 4. 安全状态

### 4.1 上电默认状态

- C07A：左右轮滑行，电机 disarm，等待按键。
- STM32：STEP 停止，DIR 固定安全值，D36A `EN` 保持低电平休眠。
- K230：只启动视觉和图传，不产生任何执行器控制。
- D36A `EN` 必须具有外部默认下拉或等效硬件失能，不能依赖 STM32 上电后的第一条软件指令。

### 4.2 允许使能条件

D36A 只有同时满足以下条件才能使能：

1. STM32 启动自检通过；
2. MS42CG 反馈有效；
3. K230 数据连续、时间戳新鲜且质量合格；
4. C07A 给出对应任务的运行许可；
5. 没有电源、通信、角度越界或控制周期故障。

任一条件失效，STM32立即停止 STEP 并撤销 D36A 使能。C07A收到 STM32 故障后按任务规则停车，不能继续完成动态项目。

### 4.3 必须记录的故障

- K230 通信超时；
- C07A 通信超时；
- 视觉丢球或质量不足；
- MS42CG A/B 非法跳变；
- 摆杆角度越界；
- 控制周期超时；
- D36A 未按预期失能；
- 电源复位、看门狗复位；
- 钢球接近凹槽机械边界。

## 5. IO 冻结原则

当前不在本计划中写死具体引脚。正式分配前必须完成 STM32F103RCT6 开发板的原理图/连接器复核，并满足以下外设需求：

| 需求 | STM32 资源类型 |
|---|---|
| K230 通信 | 1 路独立 UART，优先 DMA RX |
| C07A 通信 | 1 路独立 UART，优先 DMA RX |
| D36A STEP | 硬件定时器输出；禁止主循环软件翻转 GPIO |
| D36A DIR/EN | 独立 GPIO；EN 必须具备硬件默认失能 |
| MS42CG A/B | 定时器编码器模式 |
| MS42CG PWM | 定时器输入捕获，若台架确认需要 |
| MS42CG Z | EXTI 或定时器输入，若台架确认需要 |
| 控制周期 | 独立硬件定时器 |
| 故障恢复 | 独立看门狗 |
| 调试 | 保留 SWD；不得为了普通 IO 牺牲下载恢复能力 |

冻结 IO 时还必须同时检查：

- 3.3 V/5 V 电平兼容；
- 上电、复位和下载期间的默认电平；
- JTAG/SWD 复用；
- 定时器通道冲突；
- UART 与 USB/板载外设冲突；
- 连接器是否真实引出；
- 接地与电源回流。

## 6. 分阶段实施

任何阶段未通过验收门，不进入下一阶段。

### 阶段 0：架构与边界冻结

实施内容：

- 唯一架构写入 README、AGENTS、硬件清单和本计划；
- STM32F103RCT6 实物型号与旧校赛工程目标核对；
- 删除其他控制器方案；
- 保持当前纯循迹固件可构建、可恢复。

验收门 G0：

- 活动文档中只有本计划规定的三板架构；
- 没有提前生成 STM32/K230/D36A 运行代码；
- 当前 C07A 接线和行为未被架构文档修改。

### 阶段 1：完成 C07A 的 H-R02 基线

实施内容：

- 保持当前 CD4051、TB6612、BLS 和 OLED 接线；
- 完成官方尺寸赛道整圈测试；
- 加入题目要求的计时显示和 A 点停车逻辑前，先独立验证循迹全圈；
- 记录整圈时间、停车偏差、脱线情况和原始视频。

验收门 G1：

- 官方尺寸场地连续完成至少 3 圈；
- 单圈 `≤20 s`；
- 停车偏差 `≤2 cm`；
- 车身投影不完全离开轨迹；
- 没有 tick overrun、ADC 或电机安全故障。

### 阶段 2：STM32F103RCT6 最小板级验收

实施内容：

- 确认开发板供电入口、晶振、复位、启动配置和 SWD；
- 从旧校赛工程只提取芯片族与板卡使用经验；
- 建立新的最小 STM32 工程；
- 验证系统时钟、GPIO、两路 UART、定时器、DMA 和看门狗；
- 测量控制周期抖动。

验收门 G2：

- 冷启动、复位、重新下载均可靠；
- 两路 UART 可同时收发且无丢包；
- 定时器输出频率和控制 tick 与仪器测量一致；
- 看门狗能进入确定的安全状态。

### 阶段 3：D36A 失能与开环台架

前置条件：Q-005、Q-006 中与台架上电直接相关的项目已关闭。

实施内容：

- 确认 D36A V1.1 拨码、限流、电机额定电流和线序；
- 先不安装钢球，验证 EN 上电默认休眠；
- 使用硬件定时器产生 STEP；
- 验证 DIR、启停、加减速和急停；
- 测量驱动温升、电源纹波和失能响应。

验收门 G3：

- MCU 断电、复位、下载和通信中断时 D36A 不误动作；
- STEP 频率/脉宽满足驱动要求；
- 急停后执行器进入确定的失能状态；
- 连续运行无过流、异常温升或丢步迹象。

### 阶段 4：MS42CG 反馈台架

实施内容：

- 接入 A/B，确认每转计数、相序和方向；
- 评估 PWM 与 Z 是否确有必要；
- 建立角度零点、软限位和非法跳变检测；
- 验证电机正方向、编码器正方向和摆杆角度正方向一致。

验收门 G4：

- 往返运动计数可重复；
- 零点漂移和回程误差有数据记录；
- 非法跳变、断线和静止噪声可检测；
- 超过软限位时立即停止并失能。

### 阶段 5：摆杆角度闭环

实施内容：

- 不放钢球，完成摆杆机械零点和活动范围测量；
- 先位置环，再加入速度/加速度限制；
- 完成目标角度阶跃、往返和扰动测试；
- 确认机械间隙、回程误差和最大安全角度。

验收门 G5：

- 目标角度稳定，无持续振荡；
- 不碰机械限位；
- 通信或反馈故障时安全失能；
- 重复测试误差满足后续滚球控制预算。

### 阶段 6：K230 钢球视觉与图传

实施内容：

- 固定 GC2093，使画面覆盖完整摆杆；
- 标定像素到摆杆毫米坐标；
- 输出 `x_mm`、帧序号、时间戳和质量；
- 测试遮挡、反光、刻度线和摆杆运动；
- 同时验证实时图传、录像和回放。

验收门 G6：

- 全摆杆范围位置误差满足滚球闭环预算；
- 有效帧率、端到端延迟和抖动有实测数据；
- 丢球和误检能正确降低质量或置无效；
- 图传连续稳定，录像完整可回放。

### 阶段 7：K230—STM32 通信

实施内容：

- 冻结二进制协议版本、单位、字节序、CRC 和超时；
- 使用回放数据验证正常、重复、乱序、延迟、CRC 错误和断线；
- STM32 建立时间戳新鲜度判断和测量滤波；
- 通信异常时保持 D36A 失能。

验收门 G7：

- 两小时连续通信无未检测数据损坏；
- 所有故障注入均进入预定安全状态；
- 恢复必须经过重新 READY/ARM 流程，不能自动带故障续跑。

### 阶段 8：静态滚球闭环与 H-R03

实施内容：

- 建立钢球位置外环、摆杆角度内环；
- 从小角度、低速度开始整定；
- 加入目标斜坡、积分限幅、角度限幅和视觉超时；
- 完成 `O → +5 cm → -5 cm`。

验收门 G8：

- 全过程 `≤5 s`；
- `+5 cm` 与 `-5 cm` 最大绝对误差均 `≤1 cm`；
- 连续多次测试不掉球、不撞机械边界；
- 保留位置、角度、控制量和视频原始记录。

### 阶段 9：C07A—STM32 联控与安全互锁

实施内容：

- 冻结任务、心跳、许可、状态和故障协议；
- C07A 只在 STM32 READY 时允许动态滚球任务；
- STM32 接收底盘运动量用于后续前馈；
- 进行断线、复位、急停和任一板重启测试。

验收门 G9：

- 三块板任一重启都不会导致轮电机或摆杆误动作；
- C07A 和 STM32 对任务状态理解一致；
- 任何故障都能被显示、记录并安全停止。

### 阶段 10：A→B 动态平衡与 H-R04

实施内容：

- 先低速直线，再提高到赛题速度；
- 加入底盘加速度前馈；
- 完成 A→B 的启动扰动、直线行驶和通过 B；
- 联合记录底盘速度、球位置、摆杆角度和视觉质量。

验收门 G10：

- A→B `≤8 s`；
- 钢球相对 O 的绝对误差 `≤1 cm`；
- 连续测试无失控、掉球或通信故障。

### 阶段 11：整圈居中动态平衡与 H-R05

实施内容：

- 加入弯道转向扰动补偿；
- 分别整定直道、入弯、弯中、出弯和过 A；
- 完成顺时针整圈通过 A。

验收门 G11：

- 整圈 `≤30 s`；
- 钢球相对 O 的绝对误差 `≤1 cm`；
- 完整视频、图传和控制日志可对应同一测试编号。

### 阶段 12：任意位置动态平衡与 H-R06

实施内容：

- 目标位置从固定 O 扩展为赛场指定位置；
- 对多个正负位置验证可达性、稳定性和限位；
- 完成指定点起始、整圈行驶和通过 A。

验收门 G12：

- 整圈 `≤30 s`；
- 钢球相对指定位置的绝对误差 `≤1 cm`；
- 不依赖临时修改代码或重新刷写目标位置。

### 阶段 13：整机验收与报告

实施内容：

- 按 H-R01 至 H-R06 顺序完成正式模拟验收，并记录 H-R07 的现场正式说明；
- 固化固件版本、参数、接线、拨码和机械配置；
- 汇总失败样本与裕量；
- 完成控制框图、流程图、关键代码说明和测试数据。

验收门 G13：

- 每项要求都有可复现配置、日志、视频和测量结果；
- 图传可实时显示、完整录像并回放；
- 三块板固件版本与报告一致；
- 无秘密信息、临时调试入口或未记录接线。

## 7. 软件目录边界

在对应阶段获准前，不创建空壳代码目录。最终允许存在的业务软件只有：

```text
firmware/
├─ line_tracker/          # C07A：循迹、轮电机、UI、整机任务入口
└─ ball_controller/       # STM32F103RCT6：滚球、D36A、MS42CG、互锁
k230/
└─ ball_vision/           # K230：钢球视觉、图传、录像链路
protocol/
└─ three_board_link/      # 两条跨板协议的单一规范与主机测试向量
```

历史校赛工程不复制进这些目录；只允许按文件级审查后复用通用、无硬件冲突的少量实现。
