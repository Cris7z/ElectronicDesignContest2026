# RCT6 + D36A + K230 台架实测记录（2026-08-01）

> 目的：冻结本轮实机观察、下载结果与失败边界。本文中的“实测”仅表示本次台架上确实发生过；不等同于滚球闭环、赛题或长时间稳定性通过。

## 1. 当前物理线束（用户已确认，保持不改）

| 链路 | 当前接法 | 本次结论 |
|---|---|---|
| D36A 通道 1 STEP | RCT6 `PB6 / TIM4_CH1` → `ST1` | 已由独立 1 s 电机测试证明软件输出至电机动作链路可用。 |
| D36A 通道 1 EN | RCT6 `PB8` → `EN1` | 保持现有线束。 |

| K230 单向串口 | K230 `GPIO3 / UART1_TX` → RCT6 `PA3 / USART2_RX` | 两端用户实测空闲电平均约 3.3 V；公共 GND 已核对。**连续有效帧尚未证明。** |

## 2. RCT6 下载、启动与 D36A 实测

| 项目 | 证据 / 结果 | 状态 |
|---|---|---|
| 芯片识别 | ST-Link：`device id = 0x10036414`，Flash `256 KiB`，目标电压约 `3.21 V`。 | 已确认 |
| 编译下载 | `mingw32-make` 成功；OpenOCD 多次报告 `Programming Finished` 与 `Verified OK`。 | 已确认 |
| 最初不动作原因 | ST-Link 捕获到 HardFault；`CFSR=0x00020000 (INVSTATE)`，异常堆栈的原执行地址为 `0x00000000`。 | 已定位 |
| 根因 | `stm32f103rct6.ld` 漏掉 GCC nano libc 的 `.init/.fini` 及构造数组段，导致 `_init()` 只有入栈序列、没有返回序列，启动时落入无效地址。 | 已修复 |
| 修复验证 | 补齐链接段后，以 ST-Link 复核 CPU 停在 `main()` 正常主循环，HardFault 消失。 | 已确认 |
| D36A 独立执行器测试 | 临时固件：上电/复位后指令步进电机正转 18 rpm、持续 1 s；用户现场反馈“动了”。 | 已确认 |

当前 RCT6 已刷入正式控制构建（关闭 `UART_LINK_TEST` 和 `D36A_BOOT_SELF_TEST`）。该构建能够启动，但不能声明已经获得连续 K230 有效帧或滚球闭环。

## 4. K230 → RCT6 串口本轮结果

### 已确认

1. RCT6 的“任意原始字节触发电机 1 s”诊断曾被触发；它只能证明 PA3 出现过至少一个接收事件，**不能证明帧格式、波特率或连续传输正确**。
2. 对正式 RCT6 固件做 ST-Link 内存快照时，控制时钟已运行约 `75 s`，但 `K230_RAW_RX_COUNT = 1`、`USART_RX_STA = 1`、`s_have_position = 0`、`s_good_start_samples = 0`、状态机仍为 `TASK_WAIT_FOR_VISION`。
3. 接收缓冲区没有 `$B,...` 完整记录。因此截至本记录，K230→RCT6 的**连续字节流与有效协议帧均未通过**。

### 已排除与未排除

| 结论 | 依据 |
|---|---|
| 不能把“不动”归因于 D36A 电机本体 | RCT6 修复后独立 1 s 测试已实际转动。 |
| 不能把“不动”归因于 RCT6 启动崩溃 | 链接脚本已修复，ST-Link 已确认进入 `main()`。 |
| 不能把“原始字节触发一次”写成串口链路通过 | 后续内存快照仅有 1 个字节、无有效帧。 |
| K230 UART 与当前媒体组合仍是阻塞点 | 在 `ball_app.py` 中每帧调用 UART 发布时，用户观察到 LCD/图传卡死；改为单独 UART 发送线程后仍卡死。 |
| 根因尚未最终定位 | 尚未分离“UART1 初始化冲突”“UART write 阻塞”“CanMV 多线程/媒体资源冲突”“SD 修复后资源异常”四种可能。 |
