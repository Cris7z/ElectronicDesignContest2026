# 2026 H 题小车单圈循迹固件

这是针对当前硬件重新建立的独立工程，不继承旧通用小车的 SysConfig 或灰度
传感器假设；当前实物底盘驱动为板载 D103A/TB6612。

对应的是题目中“小车从 A 点按键启动，顺时针行驶一圈并停回 A 点”的车辆任务
（官方要求编号为 2）。当前主传感器是：

```text
HiWonder LineFollower_8CH v1.0
8 路红外数字状态 / 原生 UART 115200 / 命令 1 的一字节响应
```

它不是 8 路灰度 ADC。控制环只使用传感器原生 UART 返回的一个数字状态字节；
模拟值与学习阈值不参与本闭环。

## 当前完成状态

- 已实现无硬件依赖的 5 ms 控制核心、完整单圈状态机和故障状态机。
- 已实现 C07A/MSPM0G3507 + 板载 D103A/TB6612 + 双编码器 + 八路红外 + 四线
  OLED + BLS + LED + UART0 的新 BSP。
- 新 SysConfig 已在本机 SysConfig 1.28.0 中从零生成；物理左轮使用
  `PB3/TIMA1_CCP1 + PA16/PA17`，物理右轮使用 `PB2/TIMA1_CCP0 + PA14/PA13`。
- 17 项主机严格测试通过；TI Arm Clang 5.1.1 + MSPM0 SDK 2.11 已完成
  全固件编译、链接和 Intel HEX 生成。
- 固件默认保持 `H2026_Q2_COMMISSIONED=0`。在实测参数未填写前，它只读
  传感器、显示和输出诊断，TB6612 永远不会解锁。

已通过 XDS110 下载并架空验证 TB6612：原 A 路（物理右轮）正电气命令实际后退、
编码器增量 `-5636`；原 B 路（物理左轮）同样后退、增量 `+5360`。固件已交换
逻辑左右并反转正方向，仍待架空确认前进与每米脉冲数，不能把台架测试冒充赛道已跑通。

## 为什么采用这套控制

### 1. 八位数字图案先分类，再控制

每个 `0..255` 图案都先归一化左右顺序和有效电平，再分成：

- `NORMAL`：一个连续窄块，才允许计算离散质心；
- `LOST`：没有探头命中；
- `WIDE`：一个连续宽块，可能是 A 点横线；
- `MULTI`：多个不连续块；
- `ALL`：八路全命中，单独隔离，绝不把 `0xFF` 当固定终点。

只有有效 I2C 样本且分类为 `NORMAL` 才能更新循迹误差和微分。I2C 读失败时
保留上一有效观测用于诊断，但失败字节绝不进入 PD。

### 2. 起终点不是固定码

题目的 A 点横线长 5 cm，而八路板约 10.7 cm 宽，真实图案通常不会是
`0xFF`。程序在按键起跑时采集实际 A 点图案，返程候选必须同时满足：

- 单个连续宽块，且拒绝八路全亮；
- 活跃探头数量接近起点样本；
- 与起点样本扩一位后的窗口有足够重合；
- 图案中心仍在车体中部；
- 已离开起点，并同时通过最短里程和最短时间门；
- 连续确认 25 ms。

终点第一次合格边沿的编码器里程会被锁存，停车目标是：

```text
终点边沿里程 + 实测“传感器到车体规定参考点”的距离
```

因此不使用会随电池、速度改变而漂移的固定延时停车。

### 3. 两层闭环

- 外层：变增益、低通微分的数字红外 PD，偏差越大，转向增益越高并自动降速。
- 内层：左右轮独立速度 PI，包含 `kS + kV*v` 前馈和条件积分抗饱和。
- 目标速度有加减速斜坡；两轮超限时共同缩放，保持转弯比例。
- 已留椭圆赛道曲率前馈。只有确认 A 点确实位于配置假定的直线入口，并用
  里程日志核对切弯点后，才把
  `H2026_Q2_STADIUM_FEEDFORWARD_VERIFIED` 改为 1。

当前起调目标是直线约 `0.40 m/s`、半圆约 `0.35 m/s`。6.142 m 一圈的理想
时间约 16.9 s，给 20 s 限值保留了启动、停车和现场扰动余量。这些速度不是
未经实车验证的成绩承诺。

### 4. 故障行为

- I2C 短暂失败和物理丢线分别计时、分别降速，超过硬门限进入故障。
- `WIDE/MULTI/ALL` 在非起终点区域持续出现会按丢线处理。
- 普通传感器故障先 `00` 滑行，车速足够低或 150 ms 上限到达后短时电刹；
  BLS 长按急停直接电刹。
- 5 ms 前台丢周期或编码器持续非法跳变时，应用层立即撤销驱动并滑行，故障
  原因单独保留，不伪装成急停。
- 还会检查单周期编码器增量是否超过目标最高轮速的两倍，并监测“目标速度和
  占空比持续非零、实测速度仍近零”300 ms 的堵转/断线情形；触发后撤销驱动。
  这些阈值仍须用架空阶跃日志复核。
- TB6612 非零方向反转必须先完整滑行至少一个 5 ms 周期，不能同拍切换方向脚。
- 停车超过目标容差会报 `STOP_OVERSHOOT`，不能把“已经冲过头”判成成功。

## 实车解锁前必须填写

编辑 `app/h2026_q2_app_config.h`，逐项填入：

1. 寄存器 5 的目标有效电平；
2. bit0 是否位于传感器左侧；
3. 左右编码器前进符号；
4. 左右电机电气正命令对应的物理前进符号；
5. 左右各自的 `m/count`；
6. 实际轮距；
7. 终点横线边沿到车体规定参考点的停车距离；
8. PA18 按下电平。

然后才把 `H2026_Q2_COMMISSIONED` 改成 1。任何一项仍是哨兵值，程序都会继续
显示 `CAL LOCK`，不会驱动电机。

## 上车顺序

1. 先确认 C07A 与 S27F/S28A 实物版号；D103A/TB6612 保持插接，板载蓝牙必须拔下。
2. MPU6050 保持插在 H5，不做分线。实物已确认 H8 的 PB6/PB7 信号针不连到
   MCU，因此 HiWonder 保留 `H8-5→5V、H8-4→GND` 供电，并将信号改为
   `U3-4 (PB16)→SCL、U3-3 (PB17)→SDA`。U3-2 是 3.3 V，**不得**接传感器
   VCC；不要把四芯传感器插头硬插到六芯座。
3. 已实测传感器单独上 5 V 时 SDA/SCL 空闲均为 3.3 V；接线后再次确认约 3.3 V。
   本固件以约 33 kHz 开漏软件 I²C 运行，只拉低或释放高阻；若任一线超过约 3.6 V，
   断电后加双向 I²C 电平转换。
4. 保持 `COMMISSIONED=0` 下载诊断固件，只看 OLED/UART 的 `RAW`，逐个遮挡
   八个探头，确认有效电平和左右顺序；在最终安装高度重新做一键学习。
5. 断开动力或架空车轮，手转左右轮确认编码器符号和非法跳变计数，卷尺标定
   左右 `m/count`；再用阶跃日志核对最大单周期计数和 300 ms 堵转门限。
6. 通过独立低占空比架空试验确认左右电机方向。未完成这一步不得直接打开
   比赛模式。
7. 先以 `0.20 m/s` 跑直线速度环，再跑完整低速单圈；每次只增加
   `0.05～0.10 m/s`。
8. 在 A 点反复测传感器边沿到最终车体参考点的距离，调停车减速度和偏移，
   至少做 20 次停车统计后再追求 20 s 内速度。

当前 SysConfig 是按冻结引脚表生成并验证过的候选配置；仓库硬件契约仍要求在
实物版号确认后才允许把它视为最终上车配置。
